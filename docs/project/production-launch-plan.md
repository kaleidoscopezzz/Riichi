## 方案与写入边界

- 保留Docker Compose、Nginx、Gunicorn/Django和PostgreSQL。增加Caddy为唯一公网80/443入口；生产使用Let's Encrypt，证书和ACME状态用独立卷持久化。Nginx仅内部HTTP，继续提供React、API代理及登录限流。
- edge只供Caddy出网；proxy、web、data均内部网络。Caddy固定proxy地址可配置，Nginx仅信任该精确地址并核对原TCP对端，覆盖传给Django的代理头。限流按经过验证的真实IP；Django保持Session/CSRF/Secure Cookie，不开放全局CORS。
- 沿用全部历史身份、业务规则、迁移、Tag和证据。0005增加抽签作废字段/约束；0006仅新增释放原因并复制已释放旧行的reason，不改旧reason。新增验证工具比较旧schema列和完整数据，不编辑历史迁移。
- 完整4/8/12/16人赛事、故障与并发测试仅在独立QA库/卷。第二阶段默认沿用服务器现有库，缺库空建；不导入本地Owner SQLite。正式环境仅管理员登录、读取及安全检查，不生成测试选手/赛事。
- 新运维入口分离只读预检、目标绑定计划和执行。执行前停写、一致备份、新库恢复、迁移演练、旧列投影及完整manifest一致后才能生产迁移。失败保留维护态与证据，不自动回滚数据库或重放不确定写入。
- 主集成者负责release/preflight/smoke、CI及E2E；部署工程负责Caddy/Compose/Nginx/QA拓扑；后端验证负责schema/迁移清单；文档负责人维护本计划、操作手册和实际报告。共享根配置由主集成者整合。
