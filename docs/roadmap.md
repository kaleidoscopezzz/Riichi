# 开发路线

本路线用于划分后续任务边界，不表示尚未实现的功能已交付。各阶段均需要 Planner 下发具体任务与验收标准，TBD 先明确再进入受影响的业务实现。

| 阶段 | 目标 | 当前状态与进入条件 |
| --- | --- | --- |
| Foundation / F0-01 | 后端工程、健康 API、前端基础布局和五页占位、设计基础、环境管理、测试及工程文档 | 已完成并建立正式基线 baseline/F0-01。 |
| Foundation / 首次基线 | 建立通过验收的本地 Git 基线，再同步 GitHub，记录同一 Commit 与验证证据 | 已建立，Commit 94a1fec747806682602dd24f7edbbcc4e27d07f0。 |
| V1.0 / 账号与基础资料 | F0-02 系统账号注册认证与选手档案 | 已正式验收，基线 baseline/F0-02（59be947ca133dbe18a63dcdc99e55a3243daed51）。 |
| V1.0 / F0-03设备资源 | 麻将机台账、状态、退役、数据库容量约束 | 已实现并自检，待Planner验收；不含赛事占用调度。 |
| V1.0 / 赛事领域 | 独立 Tournament 领域对象、个人赛配置、4/8/12/16 人、1～6 轮、最多 4 台设备 | 后续任务；依赖基础资料与明确的领域验收。 |
| V1.0 / 分桌与成绩 | 首轮随机、后续累计积分降序每 4 人一桌、管理员录入半庄终局点数 | 后续任务；同点顺位及异常流程须先确认。 |
| V1.0 / 计分与冠军 | 可配置开局点数/返还原点/Uma、自动 Oka、累计积分、完赛个人冠军 | 后续任务；最终同分决胜等 TBD 须先确认。 |
| V1.0 / 集成与发行 | PostgreSQL 环境验证、安全与业务回归、部署及发行验收 | 实现完成后独立规划，当前没有生产部署。 |
| 未来版本候选 | 微信群赛事发布、报名、账号绑定、赛事播报 | 不属于 V1.0；待独立需求确认。 |

不引入微服务、Redis、Celery 或未明确要求的竞赛赛制。后续轮次分桌按已确认规则描述，不把“瑞士轮”作为当前另行实现的功能。
