# 团队赛功能规划

状态：**规则已确认，功能已形成实现候选，未正式验收/未上线**。Owner于2026-11-10在规划后明确要求“实现功能并测试通过”，并确认TEAM-01～13。实现基线为main `8f94f2e`，工作分支`codex/team-tournaments`。个人赛仍以[F0-06统一规范](F0-06-functional-spec.md)为准；本文维护团队赛规则和实施契约，实际命令、失败记录、测试及未验证范围见[团队赛验证](project/team-tournaments-verification.md)。

## 1. 已确认的目标

| 决策 | Owner确认内容 | 规划影响 |
| --- | --- | --- |
| TEAM-01 | 不固定团队数量、各队人员数量 | 不限定四队、每队四人或各队等人数；不沿用个人赛16人总名单上限 |
| TEAM-02 | 每桌每队一人 | 每场仍是四人立直，桌内四个席位来自四支不同队伍 |
| TEAM-03 | 按整体场次比赛，队长指定出场人员，由管理员录入 | 支持自由场次赛程和逐场出场名单，个人排名不能自动代替队长选人 |
| TEAM-04 | 支持管理员设置固定位置轮：先锋、次峰、中间、副将、大将依次比赛，每位置各两场并循环 | 第二种赛程模式同样纳入规划；位置顺序、每位置场数和循环次数须明确存储，默认使用该五位置与两场 |
| TEAM-05 | 队员有效积分总和作为团队积分 | 复用Uma/Oka和Fraction计分，按实际确认成绩求和，不改成平均分或另算团队赛点 |
| TEAM-06 | 每位置场数可配置；无法完整分桌时校验并提示调整，不自动改配置 | 例如5队每位置2场不成立，可提示改4场；不添加补位选手或虚构成绩凑桌 |

“不固定数量”表示允许配置不同规模，不表示可以突破四人桌的数学条件：正式开赛至少需要四支有可用出场人员的队伍；四队、五队、六队、八队等均可规划。少于四队与TEAM-02不相容，不能自动改成同队多人同桌。

队长通过线下提交名单，由现有管理员操作系统。首版保持管理员登录、PlayerProfile与内部唯一User，不新增选手/队长账号、报名权限或微信流程。

## 2. 必须区分的赛程单位

| 单位 | 含义 | 示例 |
| --- | --- | --- |
| 队伍 | 本赛事内登记的参赛单位，可有不同数量成员 | 6支队伍，成员数可以分别为3、5、2、4、6、3 |
| 一场／一个半庄 | 一张桌的四人对局，四支不同队伍各一人 | A桌完成一次四人半庄，计为1个桌场 |
| 时段／开赛批次 | 实际可同时开打的一批桌场 | 两张物理桌可同时运行2场，共8名出场选手 |
| 位置阶段 | 固定位置模式中某一循环的一个位置，含该位置所有队伍应打的场次 | 第1循环的先锋阶段 |
| 循环 | 按位置顺序完成整套位置阶段 | 先锋→次峰→中间→副将→大将完成一次 |
| 每队场次 | 一支队伍实际参加的半庄数量 | 某位置每队2场，不等于该位置总共只有2张桌场 |

团队赛的名单容量、总场次、位置阶段和循环不套用个人赛“4/8/12/16名、1～6轮”。实际并发使用单赛事1～4张真实桌，因此同一时段至多16名上场选手，整个赛事名单和赛程可更大。实现的技术处理容量为256队、4096名成员、10000桌场、32个位置、每位置场数和循环各1～100；超过容量明确报错，不能截断或改配置。这是工程配额，不是要求固定队数或各队等人数；未将容量上限当作已完成的压测规模。

## 3. 模式一：按整体场次编排

流程：创建队伍及成员→管理员设置总桌场次→安排每场四支参赛队伍→队长指定每场出场成员、管理员录入→按物理桌分开赛时段→预览确认→逐场成绩→团队累计榜→完赛。

- 每场选择四支不同队伍，各指定一名本队登记成员；不要求所有队伍在每个时段同时出场。
- 支持整份名单一次录入，也支持在未开场的计划中逐场补齐。缺少某队出场人时允许保存计划草稿，不能生成正式座次或开场。
- 同一名选手不能在同一时段出现在两张桌；同队不同成员允许同时分赴不同桌。
- 出场名单以队长指定、管理员确认的记录为准；系统可帮助安排队伍对局，不能根据个人榜自动替换出场人员。
- 首版提供“手动安排四队”和“均衡随机安排四队”，保存实际编排与来源；不增加瑞士轮或默认避重复对手的赛制。手动模式从可行的均衡初稿开始，管理员可调整未开场的四队分组，确认/启动/开场仍逐次校验全赛各队等场。

**等场排程规则**：正式比较总积分时，各队安排相同半庄数；人员多的队伍不会仅因成员多就获得更多计分场次。若队伍数为N、总桌场次为G、每队场数为E，要求`4 × G = N × E`，即`4G`能被N整除。该条件只是席位总量校验，仍逐场验证四队不同及出场/时间冲突。

例如5队安排5个桌场，共20个席位，每队4场可成立；5队安排6个桌场，共24个席位，无法做到各队等场，会拒绝正式编排。手动编辑可以暂存待修正的分组，但不等场不能确认或开场，不自动换成平均分、补分或虚构场次。

## 4. 模式二：固定位置依次循环

管理员配置：有序位置列表、每位置每队场数K、循环次数C。默认位置名称为“先锋、次峰、中间、副将、大将”，K默认2，C默认1且可配置。位置名与顺序可在草稿中编辑，启动后冻结，不能在运行中静默换序。

每个循环按以下顺序推进：

```text
先锋：本位置计划场次全部结束并确认
  ↓
次峰：本位置计划场次全部结束并确认
  ↓
中间 → 副将 → 大将
  ↓
若还有循环：回到下一个循环的先锋
否则：检查团队排名并完赛
```

- 各队为位置指定出场成员，管理员维护映射；不要求队伍恰好有五名成员。允许同一人兼任多个位置，下周期可换人；同周期同位置由一人完成K场，该队在此位置首次开场后锁定代表。
- K表示每支队伍在该位置参加K个半庄。四队、K=2时，该位置总共2桌场；八队、K=2时，总共4桌场，可能分两张桌、两个时段完成。
- 全部队伍完成当前“循环＋位置”的规定场次并确认成绩后，才能开下一个位置；未来位置的名单可以先保存草稿。
- 同一位置的多场不要求全部使用相同四队分组，实际对局按保存的计划进行；默认允许重复对手，不暗加避重目标。
- 手动编排可在未开场计划中编辑四队分组；位置模式不在单场另选人员，保存后从各队本周期位置代表映射出场人。确认时仍校验全位置各队K场，不能通过换组给某队增加场次。
- 一场成绩尚未确认时不能把下一位置当作已经结束。补录与更正仍独立留档。

### 完整分桌校验

每个位置阶段需要`N × K`个人次，必须满足`N × K`能被4整除，且每场是四支不同队伍。不能仅检查整场比赛总人次，因为角色顺序要求每个阶段能独立完成。

| 队伍数N | 每位置每队场数K | 该位置总桌场 | 校验 |
| --- | --- | --- | --- |
| 4 | 2 | 2 | 可完整分桌 |
| 6 | 2 | 3 | 可完整分桌，按时段处理冲突 |
| 8 | 2 | 4 | 可完整分桌 |
| 5 | 2 | 2.5 | 拒绝正式生成，提示调整K |
| 5 | 4 | 5 | 可完整分桌 |
| 7 | 2 | 3.5 | 拒绝正式生成，提示调整K |
| 7 | 4 | 7 | 可完整分桌 |

示例均为规划演算，不是系统现有赛事记录。系统提示应具体说明“5队×每队2场＝10个席位，不能分成完整四人桌；可将每位置场数改为4”，由管理员主动修改，不自动改场数或新增补位人员。

若位置数为P，则总桌场数为`N × K × P × C ÷ 4`，每队总场数为`K × P × C`。四队、五位置、每位置2场、1循环，即总10桌场、每队10场；六队同样配置为总15桌场、每队10场。时段数还取决于物理桌数量及名单冲突，不能直接显示成10／15个“轮次”。

## 5. 队伍、成员及名单管理

使用赛事内队伍，不做常驻俱乐部、跨赛阵容同步或独立团队后台。

- 队伍名由管理员填写，队伍ID自动生成；队伍数量、各队成员数量独立，不强制各队等人数。
- 成员使用现有PlayerProfile选取。同一赛事内同一选手只能归属一队，可在不同赛事加入不同队伍。
- 队长只是提报名单的组织角色，不因此获得后台权限；队长可以不担任每场出场选手。
- 启动前检查队名、成员重复、管理员档案、归档人员及每场队伍/成员归属；缺项仍可存草稿。
- 启动冻结本赛事队伍/成员及昵称快照；进行中仅调整未来未开场的出场计划，成员从冻结的本队名单选择。首版不支持中途增员、转队或退赛，不通过改昵称或改FK重写历史。
- 归档PlayerProfile不等于删除已启动赛事成员；历史仍保留。本赛出场选择从冻结名单读取，不能因为eligible分页过滤就把既有成员从赛事中静默移除。
- 任何已开场／已确认场次的人员、所属队伍、位置和席位均保留稳定身份。成绩更正只更正数字，不能把积分转给另一队或另一人。

## 6. 出场计划及开赛状态

分开保存“赛程计划”和“实际已生成对局”，预先填好的名单不计为已经比赛。

| 状态 | 管理员可操作 | 保护 |
| --- | --- | --- |
| 计划草稿 | 手动模式修改四队分组，自由模式指定成员，位置模式维护本位置代表 | 有缺项可保存，不能开场；位置名/顺序/场数启动冻结 |
| 计划已确认、未开场 | 核对名单；显式撤回后重新编辑 | 记录版本、确认人/时间及撤回原因，旧版本保留 |
| 已开场 | 录入四人终局点数 | 不能改参赛者、队伍、位置、桌位或风位 |
| 成绩草稿 | 保存不完整或合计异常的点数 | 不计正式团队积分 |
| 成绩已确认 | 计入团队/个人表现；进行中可更正数字 | 完整版本及更正审计，已生成后续对局保留 |
| 赛事已完赛 | 读取最终团队冠军、贡献明细及历史 | 全部结果与规则快照只读 |

出场信息保存“队长已指定／待指定”标记和管理员确认记录；不伪造队长在线确认。位置模式分别保存每队来源，不能用一次单场修改覆盖其他队的待指定状态；未锁代表允许清空，相关未开场计划同步清空并恢复待指定。修改已确认名单须明确撤回、填写原因并留档。在每场开赛前核对四队、四人、位置/循环、设备及人员冲突，再随机四风并保存。

开赛时段使用下一批连续的已确认计划，遇到同一人重复、未确认计划或位置边界即停止本批，剩余计划留给后续时段；不越过场次补满桌数。预览展示本批实际比赛、人员和设备，再由管理员确认。逻辑桌A～D及物理桌数量首批选定，后续沿用；故障通过已有换桌入口留档。

预览及提交绑定赛事类型、计划版本、冻结阵容、出场名单、位置/循环和成绩版本。其他管理员改动未来名单后，旧面板必须显示过期并回读正确场次，不能拿同一四队成员跨位置/跨场继续提交。

## 7. 团队计分与排名

### 已确认计分

每桌继续按现有`split_rank_bonus_v1`使用四人整数终局点数、Uma及Oka计算精确个人积分；Oka仍可自动推导或独立配置0，正式确认合计必须等于4×开局点数。

团队累计积分＝本队所有实际已确认出场成绩的有效积分之和。每位队员的贡献只来自其真实出场，不把未上场、轮空或缺成绩当作0分半庄；草稿不计分，不先将各场积分舍入再累加。三份50/3应合计50，不能将页面16.67相加得到50.01。

团队未必零和，继续遵守已确认的自定义Oka、Uma条件；不添加团队赛点、胜队奖金、额外罚分或任意补正公式。首版团队模式不启用桌附加分或高高碰，不能把个人排序套成队长选人规则。

### 已确认的团队同分规则

策略`team_performance_v1`：团队总积分→队员当桌第一次数合计→队员当桌第二次数合计→公开团队抽签；不修改个人赛performance_v1。

当桌第一/第二沿用原始同点的共享名次统计，不改原Uma/Oka同分规则。团队“当桌第一次数合计”不是“整轮团队获胜次数”，页面应清楚标明。

各队的实际出场时段可能不同，首版不加入逆序逐轮积分比较，不为轮空伪造0分半庄，也不把ID/创建顺序用作决胜。团队冠军必须唯一，团队抽签带完整成绩、阵容和计划来源；同一来源同一并列组最多一条待确认记录，录入错误须填写原因作废后重录，已确认记录不能作废。

个人表现榜作为辅助信息，显示所属队伍、实际出场数、积分贡献、四位回避率、最高终局点数及当桌第一次数。同指标并列时共享名次，未出场成员不排名；不为团队完赛强制额外个人抽签，首版不设独立个人奖。

## 8. 工作台与管理员操作

赛事列表提供“创建团队赛”。草稿编辑包含队伍与成员、自由场次／固定位置循环、计分规则和编排方式；保存后到工作台预览并生成赛程。单选复用统一Select，成员多选复用player-picker及eligible分页；出场选择复用冻结赛事成员，按稳定player/participant ID去重。

团队工作台包含：

1. 团队累计榜：队名、累计有效积分、已确认/已计划场数、当桌第一合计，可展开成员贡献与比赛明细；若队伍场数不同，差异直接可见。
2. 当前时段：实际物理桌A～D、四支参赛队及出场人、位置/循环、开场/成绩状态。
3. 全赛程：生成前提示编排，生成后按计划草稿、已确认未开场、已开场待成绩、成绩已确认筛选及分页，支持查看过去和未来。
4. 固定位置进度：第几循环、当前先锋/次峰等阶段，各队本位置已确认K场的完成情况。
5. 出场名单编辑：显示队伍，选项限定本队成员；版本冲突保留输入并禁用旧确认，提供按原场次/位置显式回读，不自动替换名单后延续确认。
6. 成绩更正及历史：数字试算同时展示个人积分和对团队累计的变化；实际保存前后审计。
7. 最终结果：团队冠军及成员名单、队员贡献、规则版本、所用团队抽签和全部确认成绩。

桌面表格及手机卡片、深浅主题、键盘操作、弹层焦点、取消/乱序/IME防护沿用现有规范。只读API真实数据，不放假团队或假统计补界面。

## 9. 技术与兼容实现

### 领域边界

继续在tournaments模块扩展，团队逻辑置于team_services/team_scheduling/team_serializers/team_views，不新建User/Player体系或依赖：

| 对象 | 实现职责 |
| --- | --- |
| Tournament / TeamCompetitionSettings | 明确individual/team，保存赛程模式、场数/位置/循环与团队排名策略版本 |
| TournamentTeam | 本赛事内队伍稳定ID、队名快照及可选队长标记 |
| TeamMember | OneToOne既有TournamentParticipant并关联TournamentTeam，保存成员和队长标记；原个人参赛关系不改 |
| TeamStage | 位置顺序、循环、每队规定场数及阶段完成状态 |
| TeamMatchPlan及计划版本 | 一场的四队、出场人员、位置/循环、时段、草稿/确认/撤回审计 |
| TournamentRound | 团队模式表示实际开赛批次，不能继续把它强制限制成个人赛最多6轮 |
| RoundTable / RoundSeat / TableResult / Correction | 复用实际桌场、四风、原始点数、精确结果和更正记录，绑定已确认计划 |
| 团队抽签作用域与团队冠军引用 | 和个人participant抽签/冠军明确区分，防止相同整数ID跨类型误用 |
| TeamStageRepresentative / TeamAuditRecord | 各队各周期位置代表、来源、首次开场锁定及阵容/计划前后快照审计 |

当前个人赛的完成约束要求participant冠军、轮次限制1～6、启动名单校验最多16人、每轮结构覆盖全体有效参赛者；团队模式都需要明确分支。不能把队长填入原个人冠军FK、拿一个队员代替团队实体，或直接删除个人赛人数/轮次校验。
